## Preserved weakness and revision
The 0.1 draft was deliberately designed as a weak baseline: approved handling plus a requirement for human review was treated as enough to begin a pilot. Its current-session response proposes a live pilot before assigning the owner, review time and escalation role. That is structurally valid but substantively unsatisfactory because the case explicitly lacks those prerequisites. This is an intentional negative control, not a spontaneous failure observed in a deployed agent or an independently executed earlier session. Both baseline and final prompts and outputs were prepared in this same conversation.

Version 1.0 replaces that shortcut with stage-specific prerequisites; it distinguishes required review from staffed review, unknown funding from zero funding, and evaluation preparation from sustained operation. It links each of three priorities to a gap, responsible role and completion evidence. The same primary case now blocks live use while allowing readiness work.

## Limitations
The same assistant created, answered and reviewed the cases. Passing checks establishes saved-content properties and structural validity, not future behavior, factual accuracy or human mastery. No actual syllabi were reviewed. No savings, employee readiness, real authorization or completed pilot is claimed. Workflow practice in Program B is a hypothetical premise, not performed project work. A fresh independent ChatGPT session and human critique would strengthen evaluation. The course's bounded effort requirement favors preserving this limitation over adding unnecessary software.
