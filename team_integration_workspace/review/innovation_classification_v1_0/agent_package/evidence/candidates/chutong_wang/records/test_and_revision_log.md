# Two-cycle test and revision record

Chutong Wang | October 12, 2026 | Innovation and Disruption Agent

## Protocol

Six actual ChatGPT web runs: three cases with version 0.1, then the identical three inputs with version 0.2. Course build_prompt.py produced every packet. Each run used a separate new conversation, the existing default model selection and the same dispatch wrapper. Prompt, input and parsed response hashes and conversation URLs are in run_provenance.json. JSON-only content was extracted where the UI rendered a code block; no substantive output was rewritten. Account personalization is not controlled. These are analytical tests, not measurements of a chart agent's performance.

## What stayed stable and what changed

Across primary/contrast, the technical scope, research evidence, absence of demonstrated chart-QA results and unimplemented status remain stable. Differences in organizational conservatism do not rewrite the technology history. The general finding is compared semantically, not required to repeat exact wording.

What changes is the value-capture mechanism: the financial firm uses reporting as internal support, while the studio explicitly bills some routine analyst work. The agent identifies conditional billable-hour and client-internalization exposure in the latter. A grade difference is not forced; the second studio output appropriately abstains from a definitive grade because the financial dependence is unknown. Scope ambiguity makes the third case a stress test, not another matched contrast.

## Observed weakness and warranted change

The first borderline judgment can be mistaken for a rating of the demonstrated product when it actually concerns a future agentic workflow. Initial instructions also lack an explicit implementation gate and use broad magnitude/grade labels; the model supplies important qualifications on its own. Version 0.2 makes implementation/commercialization, magnitude and novelty separate dimensions, validates agentic scope, specifies grade thresholds, requires a non-disruption counter-case and permits abstention. No case is changed to improve the result.

The first outputs were also long: copied raw JSON contained 2,850, 2,986 and 2,457 whitespace-delimited words. Second outputs contain 1,369, 1,381 and 1,311. This is shorter, but still above the approximate 800-1100-word target. Concision is an unresolved usability limitation; not every revision requirement is perfectly enforced.

## Source and reasoning review

OECD supports implementation/novelty distinctions; ReAct supports a research capability, not enterprise chart-QA; Anthropic supplies vendor engineering distinctions/tradeoffs. Microsoft documents adjacent commercial BI assistance, not equivalent source-table checking, displacement or realized savings. Economic mechanisms use explicit constructed premises and conditional inference. No dollar savings, market shares, real company results or student source verification are invented.

## Analytical judgment and team handoff

The most defensible classification for this proposed internal workflow is potential incremental business-process innovation, not a new world-first invention or a completed organizational innovation. At the general technology level, model-directed tool actions represent an integrative capability with research and commercial-adjacent evidence; a universal breakthrough claim is not warranted by this packet.

For the primary, Low conditional business-model exposure is defensible within the narrow internal scope. For the studio, Moderate exposure is a plausible scenario if reliable substitution affects multiple billed tasks, while Low remains plausible if clients pay for assurance and tailored interpretation. Actual High/Existential exposure cannot be judged without revenue dependence, substitution and adaptive-option evidence. Greater business-model exposure is not equivalent to lower governance risk or a deployment recommendation.

Preserve the classification gates and source limits in the team system. Carry forward the borderline demo as a useful counter-case. Route technological scale to Promethean, actual spread to Diffusion, adoption posture decisions to Adoption, execution controls/readiness to Organizational Readiness and current alternative monitoring to Landscape. Never translate new-to-firm novelty into global novelty, or a scenario rating into a measured outcome.

Known limits: constructed context, no actual pilot, one response per configuration/case, same assistant-led design/review, uncontrolled account personalization, variable output length and no calibrated rating scale. Student read-through of the analysis remains necessary before submission.
